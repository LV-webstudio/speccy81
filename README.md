# Speccy81 Method

![Speccy81 Method: from idea to launch, in phases](assets/banner.jpg)

**Languages · Idiomas:** English · [Español](README.es.md)

**From idea to launch, in phases.** The Speccy81 Method is how [LV-Webstudio](https://lv-webstudio.com/) takes a
project — a product, a service, a module or an app — from the first idea to its public launch with
[Claude Code](https://code.claude.com/): research first, decide with data, design before coding, test in the
field and publish without surprises.

> **Access on request.** This repository is only a presentation. The method itself (skill, guide, templates and
> script) lives in a private repository. [Ask for access](https://lv-webstudio.com/) or commission LV-Webstudio to
> apply it to your project.

## What it gives you
- **A path in ten phases**, from the idea to the launch, where nothing is coded before the research and the
  design are approved.
- **Research with parallel agents** that start from the same verified facts, so their findings do not contradict
  each other.
- **Official sources or a warning sign**: every data point carries its source; whatever cannot be confirmed is
  marked, never asserted — including what the agents themselves claim.
- **Checklists where projects usually fail**: gaps before researching, field tests with a clean setup,
  privacy and deployment in the design, and a publication checklist before the first submission.
- **Memory that survives long sessions**: a "resume here" file and state files rewritten in full, instead of
  compacting the conversation.
- **Two modes**: start from scratch, or diagnose a project that is already under way and continue from the first
  missing phase.
- **Several machines or sessions?** It works together with [Wassup](https://github.com/LV-webstudio/wassup),
  our open plugin for Claude Code sessions that talk to each other.

## The ten phases
| Phase | |
|---|---|
| 0 | Idea and context |
| 1 | Guided exploration, question by question |
| 2 | Strategy and decision dossier |
| 3 | Deep research in parallel |
| 4 | Gap analysis |
| 5 | Audit |
| 6 | Integration into your assistant or knowledge base (optional) |
| 7 | Design, with privacy and deployment — approved before coding |
| 8 | Phased build with real and field tests |
| 9 | Publication and launch |
