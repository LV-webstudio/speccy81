# Analyse des lacunes · « que manque-t-il pour le faire avec qualité ? »

Question directrice : *qu'est-ce qui détermine la qualité du résultat final que voit le client, et est-ce couvert
par des données concrètes qu'un moteur peut appliquer ?*

Pour chaque sujet : chercher dans `connaissances/` (grep sur les termes clés) et cocher.

| Sujet | Termes à chercher | Docs qui le couvrent | Suffisant pour calculer ? | Action |
|---|---|---|---|---|
| Comment le travail est réalisé pas à pas (technique) | | | | |
| Paramètres numériques (vitesses, durées, tailles, marges) | | | | |
| Ce qui peut et ne peut pas être contrôlé sur les outils/l'équipement | | | | |
| Simulation ou validation avant de le faire en réel | | | | |
| Conditions extérieures (météo, lumière, heure de la journée, saison) | | | | |
| Sécurité, urgences et incidents | | | | |
| Cas limites (environnements difficiles, pannes) | | | | |
| Post-traitement et livraison (formats, contrôle qualité) | | | | |
| Automatisation du post-traitement | | | | |
| Exemples réels (fichiers, échantillons) | | | | |
| Formation de l'équipe | | | | |
| Risques professionnels et juridiques spécifiques | | | | |
| **Essais avec des données réelles ou en usage réel** (y a-t-il un banc minimal ? a-t-il déjà été essayé ?) | | | | |
| **Confidentialité et données minimales** (ce qui est lu, stocké et envoyé ; RGPD) | | | | |
| **Déploiement et systèmes existants** (où il vit, à quoi il se connecte, ce qui se passe s'il est déplacé) | | | | |

Seules les lacunes réelles donnent lieu à un nouveau bloc de recherche. Répéter jusqu'à ce qu'il ne reste plus
de lacune importante. Tout ce qui dépend de conditions (météo, lumière, données du client) doit
aboutir dans un **sélecteur** avec des règles, pas dans du texte libre.
