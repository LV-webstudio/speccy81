# Gap analysis · «what is missing to do this with quality?»

Guiding question: *what determines the quality of the final result the customer sees, and is it covered
with concrete data that an engine can apply?*

For each topic: search `knowledge/` (grep for key terms) and tick.

| Topic | Terms to search | Docs that cover it | Enough to calculate? | Action |

| External conditions (weather, light, time of day, season) | | | | |
| Safety, emergencies and incidents | | | | |
| Edge cases (difficult environments, failures) | | | | |

| **Tests with real data or real use** (is there a minimal bench? has it been tried already?) | | | | |
| **Privacy and minimal data** (what is read, stored and sent; GDPR) | | | | |
| **Deployment and existing systems** (where it lives, what it connects to, what happens if it moves) | | | | |

Only real gaps generate a new research block. Repeat until no important gaps
remain. Anything that depends on conditions (weather, light, client data) must
end up in a **selector** with rules, not in loose text.
