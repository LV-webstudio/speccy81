# Analisi delle lacune · «cosa manca per farlo con qualità?»

Domanda guida: *che cosa determina la qualità del risultato finale che vede il cliente, ed è coperto
con dati concreti che un motore può applicare?*

Per ogni argomento: cercare in `conoscenza/` (grep dei termini chiave) e spuntare.

| Argomento | Termini da cercare | Documenti che lo coprono | Basta per calcolare? | Azione |
|---|---|---|---|---|
| Come si svolge il lavoro passo per passo (tecnica) | | | | |
| Parametri numerici (velocità, tempi, dimensioni, margini) | | | | |
| Cosa si può e non si può controllare su strumenti/attrezzatura | | | | |
| Simulazione o validazione prima di farlo davvero | | | | |
| Condizioni esterne (meteo, luce, ora del giorno, stagione) | | | | |
| Sicurezza, emergenze e incidenti | | | | |
| Casi limite (ambienti difficili, guasti) | | | | |
| Post-elaborazione e consegna (formati, controllo qualità) | | | | |
| Automazione della post-elaborazione | | | | |
| Esempi reali (file, campioni) | | | | |
| Formazione del team | | | | |
| Rischi lavorativi e legali specifici | | | | |
| **Prove con dati reali o uso reale** (c'è un banco minimo? è già stato provato?) | | | | |
| **Privacy e dati minimi** (cosa si legge, si conserva e si invia; GDPR) | | | | |
| **Distribuzione e sistemi esistenti** (dove vive, a cosa si collega, cosa succede se si sposta) | | | | |

Solo le lacune reali generano un nuovo blocco di ricerca. Ripetere finché non restano
lacune importanti. Tutto ciò che dipende da condizioni (meteo, luce, dati del cliente) deve
finire in un **selettore** con regole, non in testo sparso.
